# audiloc

*[Read in English](README.en.md)*

Кроссплатформенный (Linux/Windows/Android) музыкальный плеер с
автоматической P2P-синхронизацией библиотеки (треки, теги, избранное,
плейлисты) между устройствами в локальной сети — без облака и без
центрального сервера.

Статус: **1.0.4**. Обнаружение, сопряжение с подтверждением, синк
метаданных, передача аудиофайлов и обложек, аккаунты/профили,
"Поделиться" треком/альбомом между устройствами — всё проверено вживую
на реальных устройствах (Linux + Android). Дедупликация — пока только
грубая эвристика (не `chromaprint`). Настройки устройства (тема/язык),
подсветка текущего трека, клавиатурные/медиа-шорткаты и локальное
восстановление сессии — проверены вживую; сетевая синхронизация
состояния воспроизведения и удалённое управление сопряжёнными
устройствами — новое и помечено экспериментальным (выключено по
умолчанию), живая многоустройственная проверка ещё не сделана.
Подробности и явные ограничения: [`docs/roadmap.md`](docs/roadmap.md).

## Возможности

- Библиотека: импорт папки → авто-извлечение тегов и обложек → sha256
  файла как id трека (идемпотентный повторный импорт). Долгий тап
  (или правый клик на десктопе) по треку — меню: редактировать
  (название/исполнитель/альбом/жанр/обложка), добавить в плейлист,
  поделиться, удалить.
- Плеер: мини-плеер снизу + полноэкранный (свайп вверх/тап, свайп вниз —
  свернуть обратно), очередь, избранное — офлайн-first, без ожидания
  сети. На Android — уведомление воспроизведения, управление с
  лок-скрина и кнопки гарнитуры/Bluetooth (`audio_service`,
  `lib/services/playback/audiloc_audio_handler.dart`). Между вкладками
  можно переключаться и свайпом, не только тапом по нижней панели.
  Текущий трек подсвечивается в списках; повторный тап по нему —
  пауза/продолжить, а не перезапуск с начала. На полноэкранном плеере —
  случайный порядок и повтор (весь список по кругу — по умолчанию, или
  один трек), docs/adr/0031-shuffle-and-repeat.md.
- Пробел (пауза/плей), стрелки (перемотка) и аппаратные медиаклавиши
  play/pause/next/previous — пока окно в фокусе; шаг перемотки и
  вкл/выкл — в Настройках (docs/adr/0029).
- Состояние воспроизведения (трек + позиция): локальное восстановление
  после перезапуска приложения — **включено по умолчанию**, никогда
  никуда не отправляется. Отдельно, независимо и **выключено по
  умолчанию** (экспериментально) — синхронизация этого же состояния
  между сопряжёнными устройствами: раздельные тумблеры "отправлять"/
  "принимать", входящее состояние с другого устройства предлагается
  ненавязчивым уведомлением, а не блокирующим диалогом
  (docs/adr/0029-playback-state-sync.md).
- Удалённое управление воспроизведением — устройство может разрешить
  (выключено по умолчанию, экспериментально) другим уже сопряжённым
  устройствам управлять собой по локальной сети: play/pause/next/
  previous и живая полоса прогресса прямо в списке "Устройства";
  долгий тап/правый клик — запустить на нём то, что играет здесь, или
  выбрать трек из того, что там реально есть локально
  (docs/adr/0030-remote-playback-control.md).
- Плейлисты: создание, множественный выбор при добавлении треков (с
  поиском), удаление/переименование, порядок с дробным индексом
  (docs/data-model.md), обложка — из одного из своих треков или
  картинка из файла.
- Профили: несколько человек могут делить одно устройство — у каждого
  своя библиотека и свой список сопряжённых устройств (отдельная
  локальная БД на профиль); удаление профиля — необратимо, с
  подтверждением вводом имени. Один человек, два своих устройства —
  "Ждать сопряжения" превращает второе устройство в копию первого
  (docs/adr/0013, docs/adr/0020).
- Устройства: список сопряжённых узлов с online/offline, автоматический
  синк с уже сопряжёнными при обнаружении в LAN, бейдж "синхронизировано
  N изменений". Сопряжение — только по явному подтверждению с обеих
  сторон ("Найдено рядом" → "Добавить" → диалог "Разрешить/Отклонить"
  на другом устройстве) и **только для одного и того же профиля** —
  сопряжение разных профилей запрещено (docs/adr/0017); отвязать
  устройство можно в любой момент.
- "Поделиться" — отправить конкретный трек или альбом любому видимому
  поблизости устройству, независимо от профиля и без сопряжения;
  принимающая сторона видит превью (название, обложка) перед тем как
  принять (docs/adr/0017).
- Передача файлов — встроенная, без сторонних программ: HTTP-сервер
  и клиент audiloc сами докачивают недостающие треки с online-пиров
  в локальной сети, с докачкой при обрыве (docs/adr/0010).
- Настройки (шестерёнка на вкладке "Устройства") — тема (светлая/
  тёмная/системная, реально применяется ко всем экранам, не заглушка),
  язык (русский/английский, выбор при первом запуске или позже здесь),
  все настройки из пунктов выше, "Стереть все данные" (все профили на
  устройстве, двойное подтверждение) и "О приложении" на отдельном
  экране (docs/adr/0027-localization.md, docs/adr/0028-settings-screen-and-theming.md).
- "О приложении" — автор, версия, лицензия и краткое руководство по
  менее очевидным функциям прямо в приложении (docs/adr/0024).

## Архитектура

Подробно — [`docs/architecture.md`](docs/architecture.md) (со
схемами) и [`docs/data-model.md`](docs/data-model.md) (таблицы БД).
Обоснование ключевых решений и выбора пакетов — [`docs/adr/`](docs/adr/).

Коротко: Flutter (Riverpod, go_router) + `media_kit` для
воспроизведения + `sqlite_crdt`/`crdt_sync` (cachapa) для CRDT-слоя
метаданных и P2P-синка + `bonsoir` для mDNS-обнаружения + собственный
HTTP-сервер/клиент (`dart:io`/`dio`) для передачи файлов —
самодостаточно, без сторонних программ (docs/adr/0010).

## Установка и запуск

### Требования

- Flutter SDK (stable), Dart идёт в комплекте.
- **Linux desktop**: системные `clang`, `cmake`, `ninja`, `pkg-config`,
  `gtk+-3.0`, `mpv` (для `media_kit`). На Arch/CachyOS:
  `sudo pacman -S clang cmake ninja pkgconf gtk3 mpv`; на
  Debian/Ubuntu — `sudo apt install clang cmake ninja-build
  pkg-config libgtk-3-dev libmpv-dev`.
- **Android**: Android SDK/NDK — полная инструкция:
  [`docs/building-android.md`](docs/building-android.md).
- **Windows**: Visual Studio с C++ workload — полная инструкция:
  [`docs/building-windows.md`](docs/building-windows.md) (сборка
  возможна только на самой Windows, кросс-компиляция с Linux
  недоступна).

Никаких сторонних программ ставить не нужно — передача файлов
встроена в само приложение.

### Команды

```bash
flutter pub get

# Статический анализ
flutter analyze

# Тесты: все unit-тесты разом
flutter test test/unit/

# Тесты: все widget-тесты разом
flutter test test/widget/

# Голый `flutter test` без аргументов (unit+widget одним вызовом) в
# этой конкретной Flutter-сборке периодически зависает на shutdown —
# см. docs/testing-notes.md; двумя отдельными вызовами выше стабильно.

# Запуск на Linux desktop
flutter run -d linux

# Сборка Linux-бинаря. `--no-tree-shake-icons` обязателен: релизная
# сборка без него у некоторых Material-иконок (замечено на Icons.cast,
# Icons.cast_connected, Icons.smartphone, Icons.speaker_outlined)
# молча выкидывает глиф из шрифта, хотя иконка используется напрямую
# в коде — вместо иконки видна "тофу"-плашка/цифра.
flutter build linux --release --no-tree-shake-icons
```

Сборка под Android и Windows требует своей платформенной подготовки
(SDK/NDK, Visual Studio) — подробные пошаговые инструкции:
[`docs/building-android.md`](docs/building-android.md),
[`docs/building-windows.md`](docs/building-windows.md).

## Тесты

~140 unit-тестов + 15 widget-тестов, все проходят.

- `test/unit/data/` — репозитории (`TracksRepository`,
  `FavoritesRepository`, `PlaylistsRepository`, `ProfilesStore`,
  `PlaybackStateRepository`) на `SqliteCrdt.openInMemory()`: CRUD,
  soft-delete/восстановление, дробный порядок плейлиста.
- `test/unit/services/` — эвристика дедупликации, импорт библиотеки
  (реальное sha256-хеширование + фейковый `TagReader`), **реальный**
  P2P-роундтрип `crdt_sync` между двумя in-memory узлами по
  настоящему localhost-сокету, **реальный** HTTP round-trip передачи
  файла между `FileTransferServer`/`FileTransferClient` (включая
  докачку прерванного файла), сопряжение (`PairingService`) и
  "Поделиться" (`ShareService`) — тоже реальные HTTP-раунд-трипы, не
  моки; **реальный** WebSocket-раунд-трип удалённого управления
  (`RemoteControlServer`/`RemoteControlClient`) и запись состояния
  воспроизведения (`PlaybackStateWriter`) по всем комбинациям
  локального/сетевого сохранения.
- `test/widget/` — мини-плеер, тайл трека (офлайн-first тоггл
  избранного, подсветка текущего трека), экран библиотеки (пустое
  состояние / список), первый запуск (выбор языка/создание профиля),
  восстановление состояния воспроизведения (локальное и
  кросс-девайс — обе регрессионные проверки на реальных сценариях,
  не только "код не падает").

Про то, почему стоит запускать `test/unit/` и `test/widget/` двумя
отдельными вызовами, а не одним голым `flutter test` в этой конкретной
среде — см. [`docs/testing-notes.md`](docs/testing-notes.md).
