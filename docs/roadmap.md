# Дорожная карта: что сделано, что нет, что дальше

Статус на момент этого коммита. Сверено с этапами ТЗ (раздел 8).

## Этап 0 — UI-каркас + media_kit — ✅ сделано

Тёмная тема, вкладки, мини-плеер/полноэкранный плеер, чтение
локальной папки, отображение библиотеки.

## Этап 1 — sqlite_crdt локально — ✅ сделано

Схема `tracks`/`favorites`/`playlists`/`playlist_tracks`/`devices`
(docs/data-model.md), репозитории, offline-first избранное (тап →
мгновенное локальное обновление).

## Этап 2 — crdt_sync + bonsoir — ✅ сделано; discovery проверен вживую, синк — фикс за фиксом

`DiscoveryService`, `MetadataSyncService`, `SyncOrchestrator` — первая
живая проверка на двух физических устройствах (Android-телефон +
Linux-десктоп, одна LAN) показала: обнаружение работает сразу
(devices видят друг друга), а сам синк — нет. Причина оказалась
реальным багом: `crdt_sync_server.listen()` биндится на
`127.0.0.1`, то есть в принципе не принимает подключения снаружи
машины — см. [ADR 0005](adr/0005-crdt-sync-for-p2p-metadata.md).
Исправлено собственным accept-loop на всех интерфейсах.
test/unit/services/metadata_sync_roundtrip_test.dart (реальный
WebSocket по localhost между двумя in-memory базами) по-прежнему
зелёный после фикса. **Следующий шаг**: повторная проверка синка на
той же паре физических устройств — ещё не сделана после фикса.

## Этап 3 — Syncthing REST — ✅ код есть, ⚠️ не проверено вживую

`SyncthingClient`, `SyncthingProcessManager` — реализованы против
задокументированной формы Syncthing REST API, протестированы против
мок-сервера (test/unit/services/syncthing_client_test.dart). В этой
среде разработки нет установленного бинаря `syncthing`, поэтому
живого end-to-end прогона (запуск процесса → добавление устройства →
шаринг папки → реальная передача файла) не было. **Следующие шаги**:
1. Установить Syncthing локально и прогнать `SyncthingClient` вживую.
2. UI для связывания `devices.syncthing_device_id` с парой через
   Syncthing (сейчас есть только поле API-ключа на экране "Устройства").
3. Android: обернуть Syncthing в foreground-сервис (ТЗ п.9) — есть
   открытый форк syncthing-android как референс, не начато.

## Этап 4 — Дедупликация — ✅ грубая эвристика, chromaprint не начат

`HeuristicDuplicateDetector` (имя + длительность) — см.
[ADR 0007](adr/0007-dedupe-heuristic-for-mvp.md). FFI-биндинг к
`libchromaprint` — единственный пункт ТЗ, для которого прямо
написано "нет готового пакета"; не сделан в этом заходе. Интерфейс
`DuplicateDetector` спроектирован так, чтобы такая реализация
подключилась без изменений в вызывающем коде.

## Этап 5 — Полировка UI — частично

Сделано: тёмная тема без брендинга, обложки, мини/полноэкранный
плеер, бейдж синхронизации. Библиотека теперь с вкладками "Все /
Избранное / Жанры" — обе последние не хранятся отдельно, а вычисляются
на лету из `favorites`/`tracks.genre` (живые представления, не
поддерживаемые вручную коллекции); из экрана жанра можно
"Сохранить как плейлист" — снимок текущих треков превращается в
обычный, дальше независимо редактируемый плейлист. "Альбомы" и
"Исполнители" как такие же вычисляемые вкладки — не сделаны, но
по той же схеме, что и жанры, добавляются тривиально. Не сделано:
анимации переходов, полноценный экран очереди воспроизведения.

## Что не проверено в этой среде разработки (и почему)

- **Android-сборка**: нет Android SDK/NDK в этом окружении —
  установка не запрашивалась в рамках этого захода (это отдельное,
  отдельно согласуемое решение из-за размера и времени). Код написан
  платформонезависимо (`audio_service` под `Platform.isAndroid` и
  т.д.), нужные разрешения прописаны в `AndroidManifest.xml`, но
  сборка не запускалась на Android. Пошаговая инструкция (не
  проверенная живым запуском) — [`docs/building-android.md`](building-android.md),
  там же — честный список того, чего не хватает для полноценной
  Android-версии (runtime-запрос `READ_MEDIA_AUDIO`, `AudioHandler`
  для лок-скрина, foreground-сервис для Syncthing).
- **Windows-сборка**: невозможна с Linux-машины без кросс-тулчейна;
  не проверялась. Пошаговая инструкция (не проверенная живым запуском)
  — [`docs/building-windows.md`](building-windows.md).
- **Реальный Syncthing** и **два физических устройства в одной
  LAN** — см. выше.

## Дальше вне этих пунктов

  "Порядок и его пределы") — если частота конфликтов на практике
  окажется заметной.
- Настоящая пара ключей для id устройства вместо текущего
  MVP-упрощения ([ADR 0006](adr/0006-device-identity-without-asymmetric-crypto.md)).
- Группировка библиотеки (альбомы/жанры/исполнители) как отдельные
  под-вкладки.
- `Track.path` → `String?` + явный UI-статус "файл ещё не доступен
  локально" (сейчас: трек, известный только по синку без собственного
  импорта файла на этом устройстве, всё ещё может показать чужой,
  нерабочий путь — см. "Последствия" в
  [ADR 0009](adr/0009-local-track-paths.md)).
