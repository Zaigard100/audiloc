# Дорожная карта: что сделано, что нет, что дальше

Статус на момент этого коммита. Сверено с этапами ТЗ (раздел 8).

## Этап 0 — UI-каркас + media_kit — ✅ сделано

Тёмная тема, вкладки, мини-плеер/полноэкранный плеер, чтение
локальной папки, отображение библиотеки.

## Этап 1 — sqlite_crdt локально — ✅ сделано

Схема `tracks`/`favorites`/`playlists`/`playlist_tracks`/`devices`
(docs/data-model.md), репозитории, offline-first избранное (тап →
мгновенное локальное обновление).

## Этап 2 — crdt_sync + bonsoir — ✅ сделано, проверено на двух живых устройствах

`DiscoveryService`, `MetadataSyncService`, `SyncOrchestrator` — первая
живая проверка на двух физических устройствах (Android-телефон +
Linux-десктоп, одна LAN) показала: обнаружение работает сразу
(devices видят друг друга), а сам синк — нет. Причина оказалась
реальным багом: `crdt_sync_server.listen()` биндится на
`127.0.0.1`, то есть в принципе не принимает подключения снаружи
машины — см. [ADR 0005](adr/0005-crdt-sync-for-p2p-metadata.md).
Исправлено собственным accept-loop на всех интерфейсах; после фикса
метаданные (названия, избранное) подтверждённо синхронизируются между
Android и Linux в реальном времени.

## Этап 3 — встроенная передача файлов — ✅ сделано, ⚠️ не проверено на двух живых устройствах после фикса

Живая проверка синка метаданных вскрыла следующую проблему: сами
аудиофайлы не передавались вовсе, потому что рассчитанный на внешний
Syncthing транспорт (см. историю в [ADR 0004](adr/0004-syncthing-external-process-for-file-sync.md))
требовал отдельной установки и настройки Syncthing, которых
пользователь не делал. По явному требованию — приложение должно быть
самодостаточным — Syncthing-интеграция убрана целиком и заменена
встроенным HTTP-транспортом (`FileTransferServer`/`FileTransferClient`/
`FileSyncService`, [ADR 0010](adr/0010-built-in-file-transfer.md)):
трек с известными метаданными, но без локального файла
(`Track.path == null`, `TracksRepository.watchMissingFiles()`),
докачивается автоматически с первого online-пира, у которого он есть
(`peersWithLocalCopy()`), с резюмируемой докачкой при обрыве. Проверено
реальным (не замоканным) HTTP round-trip тестом
(test/unit/services/file_transfer_test.dart), включая сценарий
докачки прерванного файла. **Следующий шаг**: живая проверка на той
же паре физических устройств — ещё не сделана после этого фикса.

## Лок-скрин / уведомление / кнопки гарнитуры (ТЗ п.3) — ✅ сделано на Android, ⚠️ не проверено вживую

`AudilocAudioHandler` оборачивает `PlayerService` для `audio_service` —
уведомление воспроизведения, управление с лок-скрина, кнопки
гарнитуры/Bluetooth. `MainActivity` теперь наследуется от
`AudioServiceActivity`, манифест дополнен `<service>`/`<receiver>`
записями audio_service. Проверено реальной сборкой (`flutter build
apk`); живая проверка (уведомление реально появляется, кнопка на
гарнитуре реально переключает трек) — ещё не сделана, см.
[`docs/building-android.md`](building-android.md).

## Этап 4 — Дедупликация — ✅ грубая эвристика, chromaprint не начат

`HeuristicDuplicateDetector` (имя + длительность) — см.
[ADR 0007](adr/0007-dedupe-heuristic-for-mvp.md). FFI-биндинг к
`libchromaprint` — единственный пункт ТЗ, для которого прямо
написано "нет готового пакета"; не сделан в этом заходе. Интерфейс
`DuplicateDetector` спроектирован так, чтобы такая реализация
подключилась без изменений в вызывающем коде.

## Этап 5 — Полировка UI — частично

Сделано: тёмная тема без брендинга, обложки, мини/полноэкранный
плеер, бейдж синхронизации. Библиотека теперь с вкладками "Все /
Избранное / Жанры / Удалённые" — "Избранное" и "Жанры" не хранятся
отдельно, а вычисляются на лету из `favorites`/`tracks.genre` (живые
представления, не поддерживаемые вручную коллекции); из экрана жанра
можно "Сохранить как плейлист" — снимок текущих треков превращается в
обычный, дальше независимо редактируемый плейлист. Долгий тап по
треку — удалить из библиотеки (soft-delete: `tracks.is_deleted = 1`,
файл на диске не трогается); "Удалённые" — единственное место, откуда
его можно вернуть (`TracksRepository.restore`). "Альбомы" и
"Исполнители" как такие же вычисляемые вкладки — не сделаны, но
по той же схеме, что и жанры, добавляются тривиально. Не сделано:
анимации переходов, полноценный экран очереди воспроизведения.

## Что не проверено в этой среде разработки (и почему)

- **Android-сборка**: собирается и запускается — проверено на живом
  Android-устройстве (см. [`docs/building-android.md`](building-android.md)
  для полного пути через реальные проблемы AGP/Gradle/Kotlin, с
  которыми пришлось столкнуться).
- **Windows-сборка**: невозможна с Linux-машины без кросс-тулчейна;
  не проверялась. Пошаговая инструкция (не проверенная живым запуском)
  — [`docs/building-windows.md`](building-windows.md).
- **Встроенная передача файлов на паре живых устройств** — код
  реализован и покрыт реальными (не замоканными) HTTP-тестами
  локально, но повторная проверка на тех же двух физических
  устройствах, где обнаружилась исходная проблема, ещё не сделана
  — см. "Этап 3" выше.
