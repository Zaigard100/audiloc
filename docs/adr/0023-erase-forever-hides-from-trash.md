# 0023. "Стереть навсегда" убирает трек из "Удалённых", а не просто стирает файл

## Контекст

`TracksRepository.eraseFileFromDisk` ("Стереть навсегда" из
"Удалённые") стирал файл и обложку с диска, но `tracks`-строка
оставалась `is_deleted = 1` и продолжала отображаться в "Удалённые" —
просто без файла, с тем же видом, что и у трека, который ещё не
скачался с пира ("ждёт передачи с другого устройства"). Пользователь
верно указал: "Стереть навсегда" должно означать, что трек **исчезает**
из "Удалённых", а не остаётся там в подвешенном состоянии.

## Решение

Настоящий wipe строки в CRDT-таблице невозможен и не нужен — `sql_crdt`
всегда превращает `DELETE` в `is_deleted = 1` (иначе рассинхронизация
с пирами, у которых трек ещё есть). Вместо этого `TracksRepository.watchDeleted()`
теперь дополнительно исключает треки, для которых у **этого** устройства
есть `track_locations`-запись, но она сама помечена как `is_deleted = 1`
— именно это состояние `eraseFileFromDisk` уже создавал (`DELETE FROM
track_locations WHERE id = ...` — тоже становится `is_deleted = 1`, не
настоящим удалением строки), просто раньше `watchDeleted()` его ни на
что не проверял.

Это отличимо от "трек известен только по синку, файла на этом устройстве
никогда не было" — в этом случае `track_locations`-записи для этого
узла нет вообще, ни разу, ни в каком виде, так что трек по-прежнему
корректно показывается в "Удалённые" (с ним всё ещё можно сделать
"Восстановить" — синк потом сам подтянет файл откуда-то, если он есть у
пира).

`restore()` сама по себе не изменилась и по-прежнему работает
напрямую с id — просто теперь после "Стереть навсегда" для неё нет
пункта в UI "Удалённых".

  не обещает автовосстановление с пира, честно говорит "исчезнет из
