# 0020. "Ждать сопряжения" — не только на первом запуске

## Контекст

Сценарий A из [ADR 0013](0013-account-profiles.md) ("Это моё второе
устройство — ждать сопряжения") был доступен только с
`InitialProfileNameScreen` — экрана, который показывается ровно один
раз, на полностью свежей установке. Если на устройстве уже
зарегистрирован хотя бы один профиль (свой или чужой — сценарий B),
этот путь больше не проходит: единственный способ добавить профиль —
`ProfileSwitcherSheet._createDialog`, который только создаёт **пустой
именованный** профиль. Пользователь верно заметил: связать *новое*
устройство с уже существующим (на другом устройстве) профилем, когда
на этом устройстве уже есть другие профили, было нечем.

## Решение

`AudilocApp._waitForPairing()` — та же логика, что уже была (создать
профиль-заглушку "Новое устройство", выставить
`_awaitingProfileAdoption`), но теперь дважды переиспользуемая:

- На свежей установке — как и раньше, напрямую вызывает
  `_openProfile` (сессии ещё нет, закрывать нечего).
- В любой другой момент — сначала `_switchProfile(profile.id)` (тот же
  путь, что и обычное переключение профиля: закрывает текущую сессию
  как положено, потом открывает новую), и только затем выставляет
  `_awaitingProfileAdoption = true`.

Новый `waitForPairingProvider` (`lib/core/providers.dart`, тот же
паттерн, что уже есть у `switchProfileProvider`/
`joinProfileForPairingProvider`/`canJoinDifferentProfileProvider`) —
плейсхолдер, переопределяемый `AudilocApp` через
`openProfileSession(..., waitForPairing: _waitForPairing)`. Это даёт
доступ к той же логике из **любого места внутри активной сессии**, не
только с экрана первого запуска — в частности, из
`ProfileSwitcherSheet`, который теперь показывает второй пункт рядом с
"Новый профиль": "Это моё второе устройство — ждать сопряжения".
