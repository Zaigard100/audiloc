# 0004. Syncthing как внешний процесс для передачи аудиофайлов

## Контекст

Метаданные синхронизируются через CRDT-дельты (маленькие), но сами
аудиофайлы — это мегабайты/гигабайты с необходимостью chunked
transfer, докачки и версионирования при конфликте. Писать свой
протокол передачи файлов — большой и рискованный объём работы, прямо
не нужный по ТЗ п.3.

## Решение

Не писать транспорт файлов самостоятельно: запускать Syncthing как
внешний процесс (`SyncthingProcessManager`,
lib/services/sync/files/syncthing_process_manager.dart) и общаться с
уже запущенным экземпляром через его локальный REST API
(`SyncthingClient`, .../syncthing_client.dart, `localhost:8384`).

## Последствия

- AudiLoc не реализует collision-resolution для самих файлов —
  Syncthing это уже умеет (versioning, conflict-файлы).
- На Android потребуется встраивание как foreground-сервис (ТЗ п.9,
  есть открытый форк syncthing-android как референс) — не сделано в
  этом заходе, см. docs/roadmap.md.
- В этой среде разработки нет установленного бинаря `syncthing`,
  поэтому `SyncthingClient` проверен только против мок-HTTP-сервера
  (test/unit/services/syncthing_client_test.dart) — это подтверждает
  формирование запросов и разбор ответов, но не совместимость с
  конкретной версией реального Syncthing REST API. Требует живой
  проверки перед продакшеном.
- API-ключ Syncthing — единственный настоящий секрет в приложении —
  хранится через `flutter_secure_storage`
  (`SecureSettingsService`), не в обычных настройках.
