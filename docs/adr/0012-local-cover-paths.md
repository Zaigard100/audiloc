# 0012. Обложки — та же проблема и то же решение, что у путей к файлам

## Контекст

Пользователь сообщил: обложки треков не появляются на другом
устройстве — вместо картинки красный крест (стандартная иконка
Flutter "не удалось загрузить изображение").

Причина — точная копия бага, исправленного в
[ADR 0009](0009-local-track-paths.md), только для `tracks.cover_path`
вместо `tracks.path`: `LibraryImportService` кэширует обложку локально
(`$coverCacheDir/$trackId.cover`) и пишет этот **абсолютный локальный
путь** в обычный синхронизируемый столбец `tracks.cover_path`. После
синка метаданных другое устройство получает этот путь как есть —
`Image.file(File(track.coverPath!))` пытается открыть файл, которого
на этом устройстве никогда не было. При этом самого механизма передачи
обложек между устройствами не существовало вовсе — только пути "утекали"
через обычный CRDT-синк метаданных, сами байты изображения никуда не
передавались.

## Решение

Расширить уже существующую `track_locations` (а не заводить отдельную
таблицу) ещё одним нулabельным столбцом `cover_path` — та же
композитная схема `trackId:nodeId`, что уже используется для `path`,
теперь хранит и путь к локально закэшированной обложке. `tracks.cover_path`
остаётся в схеме без изменений, но с более узким смыслом: не
"путь к файлу", а просто "у какого-то устройства есть обложка для
этого трека" (булев признак — `IS NOT NULL`, значение как строка
больше нигде не читается напрямую).

`TracksRepository`:
- Каждое чтение резолвит `coverPath` через `tl.cover_path`, точно как
  `path` — `null`, если у этого устройства своей строки нет.
- `watchMissingCovers()` — треки, у которых обложка известна
  где-то (`tracks.cover_path IS NOT NULL`) и аудиофайл уже локален
  (`tl.path IS NOT NULL`), но обложки своей ещё нет. Аудио —
  обязательное условие: нет смысла тащить декоративную обложку для
  трека, который на этом устройстве ещё даже не проигрывается.
- `recordLocalCover()`/`peersWithLocalCover()` — по образцу
  `recordLocalFile()`/`peersWithLocalCopy()`.
- `backfillLocalCovers()` — по образцу `backfillLocalFileLocations()`:
  разовая проверка при старте для обложек, закэшированных этим
  устройством ещё до появления `track_locations.cover_path`.

Передача самих байтов — расширение уже существующего `FileTransferServer`/
`FileTransferClient` (docs/adr/0010), не новый порт и не новый сервис
транспорта: добавлен второй маршрут `GET /covers/<trackId>` на том же
порту 8542 (без поддержки Range — обложки маленькие, при обрыве проще
скачать заново, чем докачивать). Новый `CoverSyncService` — точная
копия `FileSyncService` по форме (следит за `watchMissingCovers()`,
качает с первого online-пира из `peersWithLocalCover()`), но отдельный
класс, а не объединение с `FileSyncService`: у обложек и аудио разные
условия готовности (обложка ждёт аудио, не наоборот) и разная
in-flight-бухгалтерия, совмещать в одном классе было бы сложнее
читать, чем два простых класса рядом.

## Последствия

- Требует миграцию схемы (v2 → v3): `ALTER TABLE track_locations ADD
  COLUMN cover_path TEXT` — безопасная аддитивная миграция, без
  переноса данных.
- Уже импортированные локально обложки не теряются — `backfillLocalCovers()`
  подхватывает их при первом запуске после обновления, так же как
  `backfillLocalFileLocations()` для аудио.
- `PlaylistsRepository.watchTracks()`/`watchItems()` получили тот же
  join на `tl.cover_path`, что и `TracksRepository` — обложки в
  плейлистах резолвятся так же корректно.
- Покрыто тестами: `TracksRepository` (сценарий "только через синк",
  `recordLocalCover`, `backfillLocalCovers` — оба случая, файл есть и
  файла нет) и реальный (не замоканный) HTTP round-trip для
  `/covers/<id>` в test/unit/services/file_transfer_test.dart.
