# 0022. Свайп между вкладками, множественный выбор при добавлении в плейлист

## Контекст

Два отдельных запроса пользователя:

1. Переключение между вкладками (Библиотека/Плейлисты/Поиск/Устройства)
   работало только по тапу на `NavigationBar` — свайпа не было.
2. Добавление треков в плейлист было устроено неудобно: тап по треку
   в шите добавления сразу добавлял его **и закрывал весь шит** — чтобы
   добавить несколько треков, приходилось открывать шит заново для
   каждого. Поиска трека в этом шите не было вообще.

## Решение

### Свайп между вкладками

`AppShell` был `ConsumerWidget` с `IndexedStack`, переключаемым только
через `context.go(...)` из `NavigationBar.onDestinationSelected`.
Теперь `ConsumerStatefulWidget`, владеющий `PageController`:

- `body` — `PageView` (не `.builder` — важно: обычный `PageView` со
  списком детей строит все страницы сразу и держит их в дереве, как и
  раньше `IndexedStack`, так что состояние каждой вкладки — позиция
  скролла и т.п. — не теряется при переключении).
- Синхронизация в обе стороны: тап по `NavigationBar` меняет маршрут
  (`context.go`) → `AppShell` перестраивается с новым `tab` →
  `didUpdateWidget` анимирует `PageController` к нужной странице. Свайп
  меняет страницу → `PageView.onPageChanged` вызывает `context.go` →
  маршрут (и, соответственно, подсветка в `NavigationBar`) обновляется
  сам. Проверка `_pageController.page?.round() != target` в
  `didUpdateWidget` не даёт зациклиться, когда обновление маршрута само
  было следствием свайпа.

### Множественный выбор при добавлении в плейлист

`PlaylistDetailScreen._showAddTrackSheet` был функцией, тап по треку
сразу вызывал `addTrack` + `Navigator.pop()`. Заменён на
`_AddTracksSheet` (`ConsumerStatefulWidget`, живёт в том же файле,
отдельного файла не заводилось — используется только отсюда):

- Поле поиска сверху — фильтрует уже отфильтрованный (по "ещё не в
  плейлисте") список по вхождению в `displayTitle`/`displayArtist`
  (регистронезависимо).
- Каждый `TrackTile` — `Checkbox` вместо иконки "+", тап по всей
  строке тоже переключает выбор (обычный паттерн для
  множественного выбора).
- Кнопка "Добавить (N)" внизу — активна только если что-то выбрано;
  жмёт `addTrack` для каждого выбранного id по очереди и только потом
  закрывает шит.

## Последствия

- Оба изменения — чисто UI, без изменений в репозиториях/схеме БД:
  `PlaylistsRepository.addTrack` уже поддерживал вызов сколько угодно
  раз подряд.
- Прямых unit-тестов не добавлено — оба изменения чисто в виджетах,
  требуют живой проверки жестов/UI, как и остальной UI-слой в проекте.
