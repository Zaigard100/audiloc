# 0005. `crdt_sync` в топологии "каждый узел — и сервер, и клиент"

## Контекст

Нужен сетевой протокол обмена CRDT-дельтами между устройствами в
локальной сети — без центрального сервера (ТЗ п.1, "без облака и без
центрального сервера").

## Решение

`crdt_sync` (тот же автор, что и cachapa CRDT-пакеты) даёт готовый
протокол синхронизации по WebSocket, но "из коробки" рассчитан на
топологию клиент↔сервер. Поскольку в AudiLoc нет выделенного сервера,
**каждое устройство одновременно**:

- слушает входящие подключения — `MetadataSyncService.startServer()`,
  свой accept-loop на `HttpServer.bind(InternetAddress.anyIPv4, port)`
  + `crdt_sync_server.upgrade()` на каждое соединение (не
  `crdt_sync_server.listen()` — см. ниже, почему);
- и подключается исходящим `CrdtSyncClient` к каждому узлу,
  найденному через discovery (`MetadataSyncService.connectToPeer`).

`SyncOrchestrator` (lib/services/sync/sync_orchestrator.dart) — клей
между discovery-событиями и этим сервисом: при появлении узла в сети
соединение открывается автоматически (ТЗ п.7, без ручных действий).

## Последствия

- Порт синка (по умолчанию 8541, `core/providers.dart`)
  анонсируется через mDNS TXT-запись рядом с id устройства (см. 0006).
- **Реальный баг, найденный при первом живом тесте на двух
  устройствах (Android + Linux)**: `crdt_sync_server.listen()`
  биндится на `InternetAddress.loopbackIPv4` — то есть принимает
  подключения **только с той же машины**. Discovery через `bonsoir`
  при этом прекрасно находил оба устройства (mDNS — на уровне ОС, не
  зависит от нашего сокета), создавая обманчивое впечатление, что
  всё почти работает, а сам P2P-синк ни разу не проходил: клиент
  честно пытался подключиться к `ws://<ip пира>:8541`, но сервер пира
  слушал только `127.0.0.1` и снаружи был недостижим. Исправлено
  переписыванием accept-loop на `InternetAddress.anyIPv4` (тот же код,
  что внутри `listen()`, но с правильным адресом) — заодно решило и
  предыдущий пункт "известное ограничение" (хендл на `HttpServer`
  теперь есть, `dispose()` закрывает его по-настоящему).
- **Проверено по-настоящему**: test/unit/services/metadata_sync_roundtrip_test.dart
  поднимает два `SqliteCrdt.openInMemory()` и реально гоняет WebSocket
  по `127.0.0.1` — тест по-прежнему проходит после смены адреса
  бинда. Фикс сделан по итогам живого теста между Android-телефоном и
  Linux-десктопом в одной LAN, где баг и обнаружился, но повторная
  проверка синка на этой же паре устройств после фикса ещё не
  проводилась — следующий шаг.
