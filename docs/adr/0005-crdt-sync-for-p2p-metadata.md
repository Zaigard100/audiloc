# 0005. `crdt_sync` в топологии "каждый узел — и сервер, и клиент"

## Контекст

Нужен сетевой протокол обмена CRDT-дельтами между устройствами в
локальной сети — без центрального сервера (ТЗ п.1, "без облака и без
центрального сервера").

## Решение

`crdt_sync` (тот же автор, что и cachapa CRDT-пакеты) даёт готовый
протокол синхронизации по WebSocket, но "из коробки" рассчитан на
топологию клиент↔сервер. Поскольку в AudiLoc нет выделенного сервера,
**каждое устройство одновременно**:

- слушает входящие подключения (`listen(crdt, port, ...)` из
  `package:crdt_sync/crdt_sync_server.dart`) — `MetadataSyncService.startServer()`;
- и подключается исходящим `CrdtSyncClient` к каждому узлу,
  найденному через discovery (`MetadataSyncService.connectToPeer`).

`SyncOrchestrator` (lib/services/sync/sync_orchestrator.dart) — клей
между discovery-событиями и этим сервисом: при появлении узла в сети
соединение открывается автоматически (ТЗ п.7, без ручных действий).

## Последствия

- Порт синка (по умолчанию 8541, `core/providers.dart`)
  анонсируется через mDNS TXT-запись рядом с id устройства (см. 0006).
- **Известное ограничение**: `crdt_sync`'s `listen()` не отдаёт
  наружу хендл для остановки внутреннего `HttpServer` — сервер живёт,
  пока жив процесс приложения. Для MVP это приемлемо (сервис на весь
  жизненный цикл приложения); для чистого рестарта сервиса
  потребовался бы патч апстрима или свой accept-loop поверх
  `dart:io`.
- **Проверено по-настоящему**: test/unit/services/metadata_sync_roundtrip_test.dart
  поднимает два `SqliteCrdt.openInMemory()` и реально гоняет
  WebSocket по `127.0.0.1` — трек, записанный на одном узле,
  подтверждённо появляется на другом. Это не то же самое, что
  проверка между двумя физическими устройствами в реальной LAN (вне
  периметра этой разработческой среды, см. docs/roadmap.md), но
  закрывает основной протокольный риск.
