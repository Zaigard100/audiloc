# 0027. Локализация: русский/английский, выбор языка при первом запуске

## Контекст

Приложение до сих пор было целиком на русском — все строки просто
захардкожены в виджетах. Запрос: добавить локализацию с возможностью
добавлять новые языки, плюс выбор языка при входе.

## Решение

### Инфраструктура

Стандартный механизм Flutter (`flutter gen-l10n`), а не что-то самодельное
— он уже умеет всё нужное: ARB-файлы как источник строк,
plural/placeholder через ICU-синтаксис, генерируемый типобезопасный класс.

- `l10n.yaml` — конфиг (`arb-dir: lib/l10n`, `template-arb-file: app_ru.arb`
  — русский исходный, а не английский, поскольку это исходный язык
  проекта; `output-dir: lib/l10n/gen`, `synthetic-package: false` — файлы
  генерируются прямо в `lib/`, не в скрытый pub-пакет, и коммитятся в
  репозиторий, а не игнорируются, чтобы `flutter analyze`/`flutter test`
  не зависели от отдельного шага кодогенерации перед собой).
- `lib/l10n/app_ru.arb` (исходный) и `lib/l10n/app_en.arb` (перевод) —
  каждый ключ на месте. Добавить третий язык — завести
  `lib/l10n/app_<code>.arb` с теми же ключами и запустить
  `flutter gen-l10n`; `AppLocalizations.supportedLocales` подхватит его
  сам.
- `lib/l10n/l10n.dart` — `context.l10n` вместо
  `AppLocalizations.of(context)!`, плюс `export` сгенерированного класса,
  чтобы никому не нужно было импортировать `gen/app_localizations.dart`
  напрямую.
- `lib/app.dart`: `AudilocApp`'s `MaterialApp`/`MaterialApp.router` (все
  4 состояния: языковой выбор, ввод имени профиля, загрузка/ошибка,
  основное приложение) получили `localizationsDelegates:
  AppLocalizations.localizationsDelegates` (готовый список из
  сгенерированного класса, уже включает
  Material/Cupertino/Widgets-делегаты — не нужно перечислять вручную),
  `supportedLocales: AppLocalizations.supportedLocales`, `locale: _locale`.

### Хранение выбора языка — на уровне устройства, не профиля

Язык — свойство этого конкретного устройства/инсталляции, не профиля:
несколько человек, делящих одно устройство (docs/adr/0013), должны
видеть один и тот же язык интерфейса независимо от того, чей профиль
сейчас активен. Поэтому не в CRDT-таблицах профиля, а в новом
`AppSettingsStore` (`lib/data/settings/app_settings_store.dart`) —
плоский `settings.json` в `appSupportDir`, по образцу уже существующего
`ProfilesStore.profiles.json`. `null` в `languageCode` значит "явного
выбора не было — следовать системной локали" (поведение Flutter
по умолчанию при `MaterialApp.locale == null`).

### Выбор языка при первом запуске

Новый `LanguageChoiceScreen` (`lib/features/profiles/language_choice_screen.dart`)
— показывается **до** `InitialProfileNameScreen`, только на действительно
свежей установке (когда `languageCode` ещё не сохранён вообще, не
только когда профилей ещё нет — иначе `InitialProfileNameScreen`
пришлось бы показывать текст ещё до того, как язык выбран). Текст на
этом экране намеренно захардкожен билингвально ("Выберите
язык\nChoose your language", кнопки "Русский"/"English" — каждая
подписана на своём языке) — это единственный экран, которому нельзя
полагаться на `AppLocalizations`, поскольку он и есть то место, где язык
только предстоит выбрать.

`AudilocApp._bootstrap()`: если install действительно свежий
(`needsInitialSetup()`) **и** `languageCode` ещё не сохранён —
`_needsLanguageChoice = true` (до `_needsInitialProfileName`). Апгрейд с
версии до этого ADR никогда не увидит этот экран: `languageCode`
никогда не задан, но `needsInitialSetup()` тоже `false` (профиль уже
есть) — язык просто следует системной локали, сменить можно из "О
приложении".

### Смена языка позже — "О приложении"

Новый `_LanguagePicker` в `about_screen.dart` (теперь `ConsumerWidget`,
был `StatelessWidget`): показывает текущий выбор (родное название языка
или "Как в системе"), тап открывает диалог с чекмарком на текущем
пункте. Простые `SimpleDialogOption`, не `RadioListTile` —
`groupValue`/`onChanged` у `Radio*` в этой версии Flutter deprecated в
пользу `RadioGroup`-предка, что для одноразового пикера на 2-3 пункта
лишняя машинерия.

Прокидывается через тот же паттерн, что уже используют
`switchProfileProvider`/`waitForPairingProvider`
(`lib/core/providers.dart`): `changeLanguageProvider` (колбэк,
реализация — `AudilocApp._changeLanguage`) и `currentLocaleProvider`
(`StateProvider<Locale?>`, зеркалит `AudilocApp._locale` внутрь
`ProviderContainer` профильной сессии — простого
`Localizations.localeOf(context)` недостаточно, им не отличить "язык
явно выбран" от "просто совпал с системным"). `_changeLanguage`
обновляет оба: `_locale` через `setState` (это то, что реально меняет
`MaterialApp.locale`) и `currentLocaleProvider.notifier.state` (то, что
читает пикер, чтобы показать текущий выбор) — без второго все точки,
подписанные через Riverpod, не увидели бы смену без пересоздания сессии.

### Извлечение строк

Прошлись по каждому файлу в `lib/features/` + `lib/app.dart` (строки на
русском в `lib/services/`/`lib/data/` — это код-комментарии на русском
про ТЗ, не строки интерфейса, не трогали). Множественное число
("синхронизировано N изменений") — через нативный ICU `plural` в ARB
(`{count, plural, one{...} few{...} many{...} other{...}}`),
`intl`-пакет сам знает правила русской и английской плюрализации —
собственноручную функцию `_plural()` из `sync_badge.dart` убрали
целиком, она больше не нужна.

Сознательно НЕ локализовано:
- `LanguageChoiceScreen` — см. выше, единственно оправданный случай.
- Родные названия языков ("Русский", "English") — билингвальный
  переключатель должен показывать имя языка на нём самом же, не в
  переводе.
- `'Новое устройство'` (`lib/app.dart`, имя плейсхолдер-профиля для
  "Ждать сопряжения") — техническое и видно доли секунды до того, как
  плейсхолдер примет настоящее имя после сопряжения; локализовать
  означало бы прокидывать `context.l10n` в метод `_AudilocAppState`,
  вызываемый на том же самом `context`, которым строится сам
  `MaterialApp` (т.е. предком, а не потомком `Localizations`) —
  ощутимая архитектурная возня ради строки, которую пользователь почти
  никогда не видит.

## Последствия

- `test/widget/*.dart` (все 4 файла) — `MaterialApp` в тестах теперь
  тоже несёт `localizationsDelegates`/`supportedLocales`/
  `locale: const Locale('ru')` — иначе `context.l10n`, вызываемый теперь
  почти в каждом виджете, падает без предка `Localizations`.
  `locale: Locale('ru')` зафиксирован явно, а не оставлен на
  системную локаль теста (обычно `en_US`) — иначе существующие
  проверки на русский текст стали бы падать сами по себе, никак не
  связанным с тем, что они реально тестируют, образом.
- `test/unit/core/profile_session_test.dart` — все вызовы
  `openProfileSession(...)` получили новые обязательные параметры
  `changeLanguage`/`initialLocale` (но-op заглушки, тесты не про язык).
- `pubspec.yaml`: `flutter_localizations` (sdk), `intl: ^0.20.2`,
  `flutter.generate: true`.
- Живая проверка — за пользователем: выбор языка на первом запуске,
  смена языка из "О приложении" применяется сразу без перезапуска,
  апгрейд существующей установки не показывает языковой экран.
