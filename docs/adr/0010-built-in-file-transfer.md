# 0010. Встроенная передача файлов вместо Syncthing

Заменяет [ADR 0004](0004-syncthing-external-process-for-file-sync.md).

## Контекст

ADR 0004 отдавал передачу самих аудиофайлов внешнему процессу
Syncthing, а AudiLoc реализовывал только REST-клиент к нему
(`SyncthingClient`). На практике это означало, что для реальной
передачи файлов пользователю нужно было отдельно установить,
настроить и связать Syncthing на каждом устройстве — сам AudiLoc
никогда не запускал и не настраивал его автоматически. При живой
проверке на двух устройствах это вскрылось напрямую: метаданные
(названия, избранное) синхронизировались через `crdt_sync`, а сами
файлы — нет, потому что Syncthing попросту не был установлен, и
никакого кода, который бы это делало за пользователя, не
существовало.

Пользователь явно сформулировал требование: приложение должно быть
самодостаточным — работать без установки и настройки сторонних
программ, и по возможности использовать уже готовые модули вместо
написания всего с нуля. Поиск по pub.dev не нашёл готового кроссплат­
форменного (Linux + Android) Dart/Flutter-пакета для P2P-передачи
файлов поверх LAN — единственные кандидаты (Wi-Fi Direct обёртки)
работают только на Android.

## Решение

Реализовать передачу файлов напрямую в AudiLoc, поверх уже
существующей инфраструктуры (`bonsoir`-discovery, `dart:io`), без
внешних процессов и новых тяжёлых зависимостей:

- `lib/services/sync/files/file_transfer_server.dart` —
  `HttpServer.bind(InternetAddress.anyIPv4, ...)` (см. также ADR про
  metadata-sync — тот же паттерн: библиотечные дефолты на loopback
  не годятся для передачи между реальными устройствами), отдаёт файл
  трека по `GET /tracks/<trackId>` с поддержкой HTTP Range для
  докачки.
- `lib/services/sync/files/file_transfer_client.dart` — клиент на
  `dio` с резюмируемой докачкой: если у `.part`-файла уже есть
  какие-то байты, шлёт `Range`-заголовок и дописывает
  (`FileAccessMode.append`), а не начинает заново.
- `lib/services/sync/files/file_sync_service.dart` — следит за
  `TracksRepository.watchMissingFiles()` (треки, известные через
  CRDT-синк, но без локального файла), находит через
  `peersWithLocalCopy()` и события discovery, у какого online-пира
  есть файл, и докачивает его в фоне, не блокируя UI.

`devices.syncthing_device_id` и связанный код (`SyncthingClient`,
`SyncthingProcessManager`, `SecureSettingsService` для API-ключа)
удалены целиком.

## Последствия

- Пользователю больше не нужно ничего устанавливать и настраивать
  отдельно от самого AudiLoc — приложение полностью самодостаточно
  для работы в локальной сети.
- AudiLoc сам отвечает за корректность передачи (докачка, целостность
  байтов) вместо того, чтобы полагаться на уже проверенную временем
  реализацию Syncthing — компенсируется реальными (не замоканными)
  HTTP round-trip тестами
  (`test/unit/services/file_transfer_test.dart`), включая сценарий
  докачки прерванного файла.
- Нет версионирования и conflict-файлов на уровне самих байтов, как
  умел Syncthing — не требуется: у трека с данным `id` (хеш
  содержимого, см. `docs/data-model.md`) байты по определению
  идентичны на всех устройствах, где он вообще есть, конфликтовать
  нечему.
- Секрет (API-ключ Syncthing) и `flutter_secure_storage` как
  зависимость больше не нужны — устранён целый класс "как безопасно
  захранить и ввести пользователем API-ключ" UX-проблем.
- Формат протокола (простой HTTP + Range, без TLS) достаточен для
  доверенной домашней LAN, но не рассчитан на враждебную сеть — не
  проблема для сценария использования (обмен только между уже
  спаренными через QR устройствами одного пользователя/семьи), но
  стоит иметь в виду, если область применения когда-то расширится.
