# 0007. Эвристическая дедупликация вместо аудио-фингерпринтинга (пока)

## Контекст

ТЗ п.3 прямо называет аудио-фингерпринтинг (дедупликация одинаковых
треков с разными именами файлов) единственной задачей без готового
Flutter-пакета: понадобился бы свой FFI-биндинг к `libchromaprint`.
ТЗ предлагает на первом этапе грубый критерий (имя + длительность +
битрейт) и явно допускает вынести фингерпринтинг за скобки MVP.

## Решение

`DedupeService` + `HeuristicDuplicateDetector`
(lib/services/dedupe/dedupe_service.dart) сравнивают нормализованное
название и близость длительности (± 1.5 сек по умолчанию). Битрейт
не используется: `audiotags` (см. 0002) не отдаёт его через
публичный API `Tag` без более глубокого чтения `Properties`, а два
сигнала (имя + длительность) уже достаточно консервативны, чтобы не
плодить ложные срабатывания.

`DuplicateDetector` — интерфейс, а не конкретный класс: будущая
chromaprint-реализация подключается без изменений в `DedupeService`
или `LibraryImportService`.

## Последствия

- Ложноотрицательные срабатывания (пропущенный дубль) безопаснее
  ложноположительных (отказ импортировать разные треки) — эвристика
  сознательно консервативна в эту сторону.
- Два разных мастеринга одного трека с разной длительностью не
  считаются дублями — это осознанный компромисс, не баг.
- Полноценный фингерпринтинг (FFI к libchromaprint) остаётся в
  docs/roadmap.md как последующая задача.
