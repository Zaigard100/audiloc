# 0018. Удаление профиля — безвозвратно, только для неактивного

## Контекст

`ProfilesStore.delete()` существовал с [ADR 0013](0013-account-profiles.md),
но был намеренно нерушительным: только убирал профиль из
`profiles.json`, файлы (база, обложки, музыка) оставались на диске.
Вызывающего экрана не было вовсе — по плану, чтобы не удалить профиль
случайно без второго подтверждения; на практике это означало, что
удалить профиль и его данные было просто нечем. Пользователь попросил
и то, и другое: удаление профиля и очистку его библиотеки/данных.

## Решение

Одна кнопка вместо двух отдельных действий (мягкое скрытие + отдельная
очистка) — по решению пользователя, проще для интерфейса ценой того,
что удаление сразу необратимо.

- **`ProfilesStore.delete(id)`** переписан: теперь не только убирает
  профиль из реестра, но и рекурсивно стирает всю его директорию
  (`profiles/<id>/` — CRDT-база, `covers/`, `synced_music/`,
  сопряжённые устройства внутри базы). Единственный вызывающий код
  раньше был только в тестах — безопасно поменять поведение без
  миграции вызовов.
- **Только неактивный профиль.** Активная сессия держит файл базы
  открытым — стереть его директорию из-под работающего процесса
  означало бы не просто потерю данных этого профиля, а более широкую
  порчу состояния. `ProfilesStore.delete()` этого не проверяет сама
  (осталась простой), проверка — на уровне UI:
  `ProfileSwitcherSheet` показывает иконку корзины только у
  **неактивных** профилей — у активного вместо неё галочка, как и
  раньше. Чтобы удалить текущий профиль, сначала нужно вручную
  переключиться на другой через тот же переключатель.
- **Подтверждение вводом имени.** Раз действие необратимо и одной
  кнопкой стирает всё, обычного "Отмена/Удалить" недостаточно —
  кнопка "Удалить безвозвратно" неактивна, пока в поле не введено
  точное имя профиля. Тот же паттерн, что уже использовался бы для
  подобных необратимых действий в проекте, просто раньше нигде не
  применялся.

## Последствия

- `test/unit/data/profiles_store_test.dart` — тест "directory is left
  on disk" инвертирован: теперь проверяет, что директория (включая
  реально записанный файл внутри) стирается.
- Роадмап-пункт "нет экрана удаления профиля" закрыт.
