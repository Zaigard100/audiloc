# 0016. Имя устройства = имя профиля + платформа/модель

## Контекст

По инварианту из [ADR 0013](0013-account-profiles.md) имя, которое
устройство регистрирует за собой и показывает пирам, всегда равно
имени активного профиля. Это осмысленно, когда у профиля одно
устройство, но ломается для сценария A из того же ADR — один человек,
два своих устройства под одним профилем (например, телефон и ноутбук):
в "Известных устройствах" на любом третьем/чужом устройстве оба показа-
лись бы одинаково, просто "Профиль 1", без возможности понять, какое
из них телефон, а какое ноутбук.

Пользователь попросил добавить к записи об устройстве что-то вроде
`Профиль1(Android 9901)` / `Профиль 1(linux-lt)` — платформу и модель.

## Решение

Регистрируемое имя устройства теперь — `"<имя профиля> (<платформа/
модель>)"`, а не голое имя профиля:

- `platformDeviceLabel()` (`lib/services/sync/device_identity_service.dart`)
  — на Android через `device_info_plus` возвращает `"Android <модель
  телефона>"`; на Linux/Windows/macOS — `"<Платформа> <hostname>"`
  (`Platform.localHostname`; хвост как в уже существующем
  `_defaultDeviceName()` — `Platform.localHostname` на Android
  ненадёжен, там реально возвращается `"localhost"`, но это не
  проблема, поскольку туда просто не заходим при `Platform.isAndroid`).
- `composeDeviceName(profileName, platformLabel)` — просто склеивает.
- `openProfileSession()` использует составленное имя вместо голого
  `profile.name` в инварианте "подтягивать имя устройства при каждом
  открытии сессии" — не изменилось по сути, изменилась только сама
  формула имени.
- `applyActiveProfileRename()` (ручное переименование профиля через
  переключатель) — то же самое: пишет в `devices` составленное имя,
  а не голое `name`. Само значение `Profile.name` (то, что видно в
  карточке профиля/переключателе) по-прежнему остаётся голым — суффикс
  относится только к тому, что видят **другие** устройства в списке
  "Известные устройства".

`platformLabel` — необязательный параметр обеих функций (по умолчанию
`platformDeviceLabel`), чтобы тесты могли подставить детерминированный
стаб вместо реального hostname/модели устройства, которые меняются от
машины к машине.

## Последствия

- Устройства одного профиля теперь различимы в списке "Известные
  устройства" — то, ради чего это делалось.
- `test/unit/core/profile_session_test.dart` обновлён: имя self-device
  теперь ожидается как `"<профиль> (TestOS)"` вместо голого имени
  профиля; тесты подставляют `platformLabel: () async => 'TestOS'`.
- Новая зависимость `device_info_plus` — только для чтения модели
  устройства на Android, никаких разрешений/пермишенов не требует.
